## 2. Детали по пунктам особого внимания

### (a) Изменения в `windows/` upstream и общие баги Mayak

1. **Пути из страницы (топ-1).** Модель угрозы та же, что в upstream: всё, что вызывает webview, считается недоверенным вводом (скрипт в странице через будущий XSS в Markdown чата, в тексте сессии и т. п.).
   - `ingest_file(path)` (`lib.rs:779-782`, зарегистрирован в `lib.rs:959`) → `files::ingest` (`files.rs:28-64`): `metadata` + `File::open` любого пути, копия в inbox, путь копии наружу. TS-обёртка `Bridge.ingestFile` (`core/bridge.ts:165`) нигде не вызывается: drop у Mayak идёт через `ingest_bytes`. Самое простое — удалить команду и обёртку.
   - `chat_send` (`lib.rs:762-771`) → `claude::send` (`claude.rs:77-107`) → `file_block(path)` (`claude.rs:260-290`): PDF и картинки читаются целиком, текст до `MAX_INLINE_TEXT`, без проверки места. Файл уходит в Anthropic под ключом пользователя, а ответ модели возвращается в страницу, так что содержимое можно вытянуть. Сейчас путь закрыт тем, что чат выключен в интерфейсе, но команда зарегистрирована (`lib.rs:956`).
   - Готовая проверка в Mayak: `launcher::prepare` (`launcher/mod.rs:403-416`) — canonicalize inbox и файла, `real.parent() == inbox`, `is_file`. Вынести её в `files.rs` (например, `files::inbox_file(path)`) и звать из `claude::send` и `launcher::prepare`.
2. **Vite (топ-2).** `vite.config.ts:48`. Upstream-фикс проверен в их CI на Windows; у нас та же раскладка (`windows/target`).
3. **Автозакрытие.** `fsm.ts:12` — простое поле, `scheduleHomeCollapse` (`fsm.ts:167-174`) берёт значение в момент планирования; `applySettings` (`island.ts:1622-1626`) только присваивает. Upstream (62e43c6) сделал сеттер, который перепланирует идущий таймер; в Mayak ещё нужно обновить `homeCollapseAt` (полоска обратного отсчёта, `island.ts:1286`). Проверка `pinned` внутри таймера, как у upstream, Mayak не нужна: `alert()` ставит `pinned` и вызывает `forceHome()`, который снимает таймеры (`island.ts:532-537`).
4. **Мёртвый тикер.** `views/ticker.ts` (баг 20 шагов, нет `top:0`) и `State.appendStep` (`core/state.ts:295-300`) не используются. Не баг, но кандидат на удаление, чтобы при обзорах upstream не принимать его за живой код.
5. **Симлинк `settings.json`.** Как в прошлом обзоре: `hookfile.rs:440` переименовывает temp поверх пути; если `~/.claude/settings.json` — симлинк (dotfiles), ссылка станет обычным файлом. Upstream теперь разрешает ссылку и на Windows (`resolve_link` в `config_file.rs`). Низкий приоритет: файловые симлинки на Windows требуют режима разработчика или прав.
6. **Порядок `wasInIsland` (из #329).** В Mac-коде переход, вызванный наведением, запускал таймер закрытия, пока мышь ещё на острове, потому что флаг обновлялся после FSM. В Mayak тот же порядок: `onCursor` обновляет `wasInIsland` только в `island.ts:1290`, а обработчики переходов читают его в `island.ts:405,411`. Сейчас это безвредно: из `hidden` остров будит полоска (`onStripTouch`, `island.ts:1197-1200`), а первый же тик опроса с мышью на острове снимает таймер (`fsm.mouseEntered` в `petit` → `clear("petitHide")`). Но если делать открытие по наведению, `this.wasInIsland = inIsland` надо перенести перед вызовами FSM, иначе остров, открытый наведением, сразу начнёт отсчёт.

### (d) Терминальные сессии и «Open» (#326, #238, #282, c90d30b)

- **Mac (#326)**: сессии из терминалов попадают на пилюлю «Claude Code» по `term_program` / `bundle_id`; «Open terminal» активирует приложение сессии, затем любой известный запущенный терминал, затем Terminal.app; вопросы и разрешения терминальных сессий по умолчанию остаются в терминале.
- **Windows upstream (c90d30b)**: при подключении релея берёт PID клиента пайпа (`GetNamedPipeClientProcessId`), идёт вверх до процесса с окном (стоп на `explorer.exe`, `svchost.exe` и т. п., до 16 уровней), запоминает по session ID (до 64 сессий), по клику поднимает окно, в заголовке которого есть имя папки, иначе первое. Классическая консоль не находится (окно у conhost).
- **Mayak**: наблюдатель знает PID агента без релея; `focus::switch_to` (`focus/mod.rs:225-257`) для Cursor и VS Code выбирает окно по папке и воркспейсам, для Claude Desktop шлёт deep link, для `Unknown` сразу открывает Проводник. Предлагаемое изменение (топ-3): для `Unknown` вызвать `win::host_windows(pid)` (обход предков уже есть, `focus/win.rs:73-96`) и выбрать окно с именем папки в заголовке, иначе верхнее окно; `Pick::Many` для двух окон одного терминала → верхнее (а не лаунчер, его для терминала нет). Логи — как сейчас, без заголовков (`focus::log_line`). Windows Terminal держит все вкладки в одном окне, так что поднимется окно, но не обязательно нужная вкладка — это стоит написать в подсказке.

### (e) Antigravity PreToolUse (#332, 4fb4330 → 66be53e) и шаблон хуков

- Суть: на PreToolUse Antigravity считает `{}` запретом; авто-`allow` из #317 был бы одобрением без клика; правильный ответ — `{"decision":"ask"}` (решает собственный запрос Antigravity). Тест upstream перебирает все пары «агент × событие» без решения и требует, чтобы ни одна не одобряла (исключение для `ask` встроено в проверку, а не в список пропусков).
- Mayak: шаблон «молчать, если не уверен» тот же — печатаем только для ожидающих событий (`hook/src/main.rs:87-93`), Claude и Codex читают пустой stdout как «нет мнения». Antigravity и Gemini Mayak не обслуживает: чужой `--agent` → выход без вывода (`main.rs:37-39`). Общего бага нет.
- Правило на будущее для ideas (e): у каждого нового агента сначала выяснить, как он читает пустой stdout и `{}` на каждом событии; у Antigravity пустого/`{}` недостаточно. Вынести ответы в таблицу «агент × событие → stdout», как `reply.rs` upstream.
- Тест, который стоит добавить уже сейчас (дёшево): перебор `Agent::{Claude, Codex}` × набор событий × `Reply::Release` / таймаут в `reply_json` с проверкой, что вывод либо пустой, либо не содержит одобрения. Сейчас это покрыто точечными тестами (`release_and_unusable_answers_print_nothing`, `hook/src/lib.rs:983`), но не перебором.

### (f) Spotify (#246, #330) и плеер Mayak

Mac-пилюля Spotify построена на AppleScript и распределённом уведомлении Spotify, обложка — по сети с хостов Spotify. Mayak получает то же для любого плеера из Windows SMTC без сети и без разрешений: название, исполнитель, обложка (`media/win.rs`, `cover_data_url`), play/pause, next, prev (`media.rs:271-285`). Переносить нечего. Из интерфейса upstream можно взять: полосу позиции с экстраполяцией времени между событиями (без таймера опроса), shuffle и repeat. В SMTC для этого есть `TimelineProperties` и `TryChange…Async` у сессии; не проверялось, как их отдаёт Spotify desktop. Громкость отдельного приложения через SMTC недоступна — не обещать.
