# Mayak: фокус-режим, плеер, статистика токенов, сессии Cowork — проекты (ночь 2026-10-07)

Статус: решения приняты без пользователя (он спит и попросил не задавать вопросов). Каждое отмечено как **Решение** и проверяется утром. Источник — `docs/superpowers/ideas/2026-10-06-mayak-next-ideas.md`.

Общие правила проекта:
- 0 % CPU в покое: никаких таймеров и опроса, пока ничего не происходит. Допускается один таймер окончания фокуса.
- Читаются только числа, имена моделей и пути проектов, но не текст.
- Существующие виды не меняются, кроме явно названных.
- Новых крейтов нет. Можно добавлять только features крейта `windows`.

## A. Фокус-режим (идеи §18)

**Цель.** Время, когда остров не отвлекает. По окончании показывается сводка того, что произошло.

- **Включение.** Кнопка в шапке острова (значок «мишень») рядом с колокольчиком.
  - Клик начинает фокус на `focusMinutes` минут, по умолчанию 25.
  - Повторный клик во время фокуса заканчивает его досрочно.
  - Пункт трея «Focus» — галочка, синхронная с кнопкой.
- **Во время фокуса.**
  - Тревоги «готово» и «ошибка» не открывают остров и не звучат. «Агент ждёт вас» (разрешение, вопрос) **пропускается**, если включено `focusLetWaitsThrough` (по умолчанию да): ожидающий агент важнее тишины.
  - Остров сам не выдвигается и при новых сессиях.
  - Курсор и `Alt+M` по-прежнему открывают его: явное действие пользователя.
  - Полоска окрашивается в фиолетовый тон как знак фокуса, статично, без анимации.
  - **Решение:** таймер окончания — один `setTimeout` на всё время фокуса, без ежеминутных пробуждений. Обратного отсчёта на полоске нет.
- **Сводка.** Каждое подавленное событие запоминается в памяти: ключ сессии, вид, время.
  - По окончании фокуса остров открывается на карточке «Focus done · 25 min», со звуком завершения.
  - На карточке: «N finished, M errors, K waited for you», список проектов с этими событиями и кнопка «OK».
  - Если событий не было: «Focus done — nothing happened».
- **Тихий режим и фокус.** Тихий режим (пауза) главнее: в паузе фокус не показывает сводку со звуком.
- **Настройки** (General):
  - «Focus length» — 25, 50 или 90 мин;
  - «Let waiting agents through» — переключатель.
- **Файлы:**
  - TS: `island/island.ts` (`handleAlerts`), `views/views.ts` (кнопка, карточка), `main.ts`, `core/state.ts`;
  - Rust: `settings.rs` (поля `focus_minutes`, `focus_let_waits_through`), `tray.rs` (галочка «Focus», синхронизация как у Pause);
  - стили.
- **Тесты:**
  - чистая функция решения «показывать ли тревогу» (фокус, пауза, вид тревоги, настройка);
  - чистая функция сводки;
  - Rust: настройки по умолчанию, совместимость старого файла настроек.

## B. Плеер — системные медиа-сессии Windows (идеи §19)

**Цель.** Видеть в острове, что играет в любом плеере, и управлять им без интеграций и токенов.

- **Rust:** WinRT `Windows.Media.Control.GlobalSystemMediaTransportControlsSessionManager`.
  - При старте вызывается `RequestAsync`. Подписки: `CurrentSessionChanged`, у текущей сессии `MediaPropertiesChanged` и `PlaybackInfoChanged`. **Всё по событиям, без опроса.**
  - Состояние: название, исполнитель, приложение (`SourceAppUserModelId`, отображается как имя: Spotify, Chrome, Apple Music), играет или пауза, доступность `next`/`prev`.
  - Событие `media` уходит в остров при каждом изменении. Команды: `media_toggle`, `media_next`, `media_prev`.
  - **Решение:** обложку пока не берём (поток `Thumbnail` — отдельная работа).
  - Features `windows`: `Media_Control`, `Foundation`, `Foundation_Collections` — сколько потребуется.
- **Остров.**
  - Строка плеера внизу домашней страницы: `▶ Название — Исполнитель · Spotify` и кнопки ⏮ ⏯ ⏭. Видна только при активной медиа-сессии.
  - **Решение:** только на домашней странице, без изменения компактного острова.
  - Настройка «Show what's playing» (General), по умолчанию включена. Выключенная отписывается от событий.
- **macOS** (при порте) — MediaRemote.
- **Тесты:**
  - чистая функция «отображаемое имя приложения по `SourceAppUserModelId`»;
  - сериализация состояния;
  - вживую — Spotify, YouTube в браузере.

## C. Глобальная статистика токенов (идеи §3)

**Цель.** Сколько токенов израсходовано по дням, проектам, агентам и моделям.

- **Решение:** живые счётчики не копим, считаем **по запросу** из файлов агентов. Это детерминированно, без двойного счёта при перезапусках и без своей «истины», которая может разойтись с файлами.
  - Claude: `~/.claude/projects/*/*.jsonl`. Записи `assistant` основной ветки (без `isSidechain`) с `message.usage`. Дата из `timestamp`, модель из `message.model`, проект — каталог проекта (`cwd` записи → корень, как в наблюдателе).
  - Codex: `~/.codex/sessions/**/rollout-*.jsonl`. Записи `token_usage_record.usage`, по одной на запрос. Дата из `timestamp`, проект из `session_meta.cwd`, модель из `turn_context.model`, если есть.
  - **Что считается:** `input`, `output`, `cache_read`, `cache_write` отдельно. «Всего» — их сумма.
- **Кэш:** `%LOCALAPPDATA%\Mayak\stats-cache.json`.
  - На каждый файл агента хранятся его размер, время изменения и уже посчитанные дневные агрегаты.
  - При открытии статистики перечитываются только изменённые файлы. Файл, который дописывается, перечитывается целиком: агрегаты по нему пересчитываются, так что дубля нет.
  - В кэше только числа, даты, имена моделей и пути проектов.
- **Когда считается.** Только при открытии вида статистики, в фоновом потоке. Пока идёт пересчёт, вид показывает «Counting…».
- **Вид.** Новая вкладка острова «Stats» (значок столбиков) рядом с домом. **Решение:** вкладка, а не часть домашней страницы, потому что домашняя по высоте занята лимитами.
  - Переключатель периода: 7 / 30 дней.
  - Итог за период.
  - Столбики по дням (сумма).
  - Топ проектов и разбивка по агентам и моделям (таблица).
- **Тесты:**
  - разбор записей обоих агентов, только числа;
  - агрегирование по дням в локальном часовом поясе;
  - кэш: неизменённый файл не перечитывается, изменённый пересчитывается без дубля;
  - испорченные строки пропускаются.

## D. Сессии агентного режима Claude Desktop (Cowork, идеи §20)

**Сначала разведка формата** `%APPDATA%\Claude\local-agent-mode-sessions\…\audit.jsonl`: типы событий, начало и конец хода, ожидание ответа, признак живой сессии. Смотрим только типы и метки времени.
- Если формат позволяет: новые сессии с агентом «Claude» и хостом «Claude Desktop», фазы working / idle / waiting. Проект — рабочая папка Cowork, если она есть, иначе проект «Cowork».
- Если формат не позволяет надёжно определить фазы: результат разведки записывается в идеи, реализации нет.

## E. MSI-установщик (идеи §12)

`tauri.conf.json`: `"targets": ["nsis", "msi"]`; в `scripts/pack.mjs` — запись `msi` (`Mayak-Windows-<v>.msi`). Проверка: локальная сборка, если WiX скачается; иначе только проверка конфигурации.

## F. Отделить Windows-код `focus/` (задел под macOS, идеи §10)

`focus::win` и его вызовы — под `cfg(windows)`. Для других систем — заглушка: окно не найдено, сработает запасной путь (открыть папку). По образцу `strip`, `hotkey`, `launcher`.

## G. Ответы на вопросы и разрешения из острова (идеи §4) — только проект

- **Claude Code — разрешения.** Есть старый путь «Allow / Deny» из Coucou:
  - хук `PermissionRequest` (`pipe.rs` → `Route::Approval`);
  - ретранслятор ждёт решения острова с ограничением по времени (`ACK_TIMEOUT`, `DECISION_TIMEOUT`); без ответа отдаёт вопрос обратно в терминал;

### G.2 Варианты

1. **Claude, разрешения — включить и довести то, что есть.**
