# Mayak, подпроект 2: переключение на окно сессии (Windows)

Дата: 2026-10-06. Статус: реализовано в ветке `feature/window-switching` (замеры S2–S4 частично не сделаны, см. §8 и §10). Основан на подпроекте 1 (`2026-10-01-mayak-multi-session-core-design.md`, PR mahach666/mayak#1). Подпроект 1 в §13 оставил точки расширения; этот документ их использует и ничего в них не меняет.

## 1. Цель и границы

**Цель.** Клик «↗ Open» на карточке или строке сессии выводит на передний план **то окно, где идёт эта сессия**: окно Cursor или VS Code с папкой проекта, окно Claude Desktop, окно Codex Desktop. Если окно найти или поднять не удалось, поведение не хуже сегодняшнего: запускается `cursor`/`code` с корнем проекта, для Desktop-приложений открывается протокол приложения, иначе Проводник.

**Принятые решения (пользователь, 2026-10-06).**
1. Объём первого выпуска: только переключение для сессий агентов (Claude Code, Codex).
2. Подход: гибрид. Свой поиск окна и подъём через Win32, запасной запуск, если окно не найдено или не поднялось.

**Вне подпроекта 2 (отложено).**
- Значки окон в заголовке проекта и связывание «проект ↔ приложения» вне сессий агентов.
- Visual Studio 2022 (окна и `.sln`), запуск недостающих приложений кнопкой «открыть проект в …».
- Выбор конкретной сессии внутри Claude Desktop и Codex Desktop, если для этого нет надёжного адреса (см. §8, замер S3).
- Окна на других виртуальных рабочих столах (§9).

**Сохраняются правила проекта.** Только Windows. Ничего не пишем в настройки других программ. Не читаем `~/.claude/ide/*.lock`. 0 % CPU при скрытом островке: подпроект 2 не вводит ни таймеров, ни опроса, работа идёт только по клику.

## 2. Что известно о системе (замеры 2026-10-06, чтение окон без действий)

| Хост | Что нашли |
|---|---|
| Cursor | Все окна принадлежат **одному главному процессу** `Cursor.exe`, класс `Chrome_WidgetWin_1`. Заголовок кончается на `<папка проекта> - Cursor`, перед ним может стоять заголовок чата или файл. |
| Claude Desktop | Одно окно `Claude`, класс `Chrome_WidgetWin_1`. По заголовку сессию выбрать нельзя. |
| Codex Desktop | Процессы `ChatGPT.exe` есть, видимого окна при замере не было (приложение, вероятно, свёрнуто в трей). Зарегистрирован протокол `codex://`. |
| VS Code | Протокол `vscode://`, окна как у Cursor (в этом подпроекте не замерялись, правило то же, что у Cursor). |
| Visual Studio 2022 | Пять процессов `devenv.exe`, заголовок `<решение> - <файл> - Microsoft Visual Studio` (для следующего шага). |

Родитель процесса агента в IDE — `extension-host` без окон; процесс Claude Desktop, который запускает агента, — не тот, что владеет окном. Поэтому владельца окна ищем не по имени exe (у Claude Desktop и у CLI он один и тот же), а по цепочке родителей.

## 3. Архитектура

Новый модуль `windows/src-tauri/src/focus/` (`mod.rs` — чистая часть и оркестрация, `win.rs` — единственное место с Win32). Он состоит из чистой части (без Win32, тестируется таблицами) и тонкого слоя Win32.

```
session_open(key)                                  [lib.rs, сигнатура не меняется, §13.5 подпроекта 1]
  ├─ session_target(snapshot, key) → (host, root)  [как сейчас]
  ├─ session_agent_pid(snapshot, key)              [новое: `SessionView.agent_pid`, только pid, `#[serde(skip)]`, в интерфейс не уходит]
  └─ focus::switch_to(host, root, agent_pid) -> Outcome
        1. win::host_windows(pid)     цепочка родителей (`ancestors`) → ближайший процесс с видимыми окнами (`host_pid_from`) → его окна; заголовки читаются только у этих окон  [Win32 + чистая логика]
        2. (в `host_windows`)         EnumWindows: видимые окна верхнего уровня, без чтения заголовков
        3. pick_window(host, root, windows) -> Pick                                           [чистая]
        4. raise(hwnd)                восстановить свёрнутое, вывести вперёд, проверить       [Win32]
        5. при Pick::None / Pick::Many / Raise::Failed → fallback(host, root)                 [запуск, как сегодня; протоколы после замера S3]
```

**Единицы и границы.**
- `pick_window` получает только данные (`WindowInfo { hwnd, title, minimized }`, `HostKind`, корень проекта) и возвращает `Pick::One(hwnd) | Pick::Many | Pick::None`. Ни Win32, ни ввода-вывода.
- `windows_of`, `host_main_pid`, `raise` — единственное место с `unsafe`/Win32 в модуле. Любая их ошибка превращается в `Outcome`, паники нет.
- `fallback` использует существующие `launcher_for` и `platform::find_on_path`/`no_console`.
- Идентичность проекта по-прежнему задаёт `paths::project_of` (корень git). Имя папки для сравнения с заголовком берётся из корня, который уже лежит в снимке.

## 4. Правила хостов

| Хост | Владелец окон | Выбор окна | Запасной путь |
|---|---|---|---|
| Cursor, VS Code | ближайший предок агента с видимыми окнами (главный процесс редактора) | заголовок, у которого сегмент перед суффиксом ` - Cursor` / ` - Visual Studio Code` (разделитель ` - `) без учёта регистра равен имени папки проекта | `cursor`/`code` с полным корнем (редактор сам находит окно с этой папкой); без лаунчера — Проводник |
| Claude Desktop | ближайший предок с видимыми окнами | единственное окно; если окон несколько, самое недавно активное по Z-порядку | `claude://` (если S3 покажет полезное действие), иначе Проводник |
| Codex Desktop | то же | то же; если окна нет (в трее) — переходим к запасному | `codex://` (в т. ч. поднимает приложение из трея, если S3 это подтвердит), иначе Проводник |
| Unknown | — | — | Проводник, как сейчас |

`Pick::Many` (два окна редактора с одинаковым именем папки) не угадываем: идём в запасной путь с полным корнем, потому что редактор различает папки по полному пути.

## 5. Подъём окна (Win32)

1. Свёрнутое окно: `ShowWindow(SW_RESTORE)`.
2. Вывод вперёд: `SetForegroundWindow`. Windows разрешает это процессу, получившему последний ввод; клик по островку считается вводом. Если вызов не удался, используем один дополнительный приём (разрешение переднего плана через `AllowSetForegroundWindow` у запускаемого лаунчера либо привязка потока ввода текущего переднего окна). Какой именно приём нужен, решает замер S1; более одного приёма не вводим.
3. Через ~150 мс `GetForegroundWindow() == hwnd`? Да → `Outcome::Focused`. Нет → `FlashWindowEx` (мигает кнопка на панели задач) и `Outcome::Flashed`.

Островок никогда не забирает фокус (`island.rs`), поэтому клик по нему не должен менять активное окно до нашего вызова.

## 6. Результат и журнал

`Outcome`: `Focused`, `Flashed`, `Launched` (запасной запуск удался), `OpenedExplorer`, `Failed`. Команда `session_open` по-прежнему возвращает `bool`: `true`, когда переключение **запущено** (неизвестный ключ, не абсолютный корень и отсутствующая папка дают `false` и ничего не делают). Само переключение идёт в короткоживущем потоке (подъём окна ждёт ~150 мс), поэтому поток интерфейса не блокируется; интерфейс возвращаемое значение не использует.

В `mayak.log` пишется одна строка с видом исхода и хостом (`session_open: host=Cursor outcome=Focused`). **Заголовки окон, имена папок и пути в журнал не попадают.** Заголовки читаются только у окон процесса-хоста и только в памяти для сравнения.

## 7. Тесты

- Таблица `pick_window` на заголовках из замеров (имена папок обезличены): одно совпадение, ни одного, два одинаковых, заголовок без суффикса, заголовок чата перед папкой, регистр, имя папки внутри другого слова (не совпадает), кириллица.
- Правила хостов: какие хосты используют выбор по заголовку, какие берут единственное окно.
- Запасной путь: выбор лаунчера или протокола по `HostKind`; корень, не являющийся абсолютным путём, ничего не запускает (как `bef6558` в подпроекте 1).
- Ручная приёмка (раздел 10): сам вывод окна вперёд автоматизировать нельзя, это правила Windows.

## 9. Границы и риски (в духе §15 подпроекта 1)

- Обход родителей не включает и не проходит `explorer.exe`: оболочка не хозяин агента, иначе мог бы подняться окно Проводника. Если у хоста нет видимых окон (например, Codex в трее), окно не найдено и срабатывает запасной путь.
- Заголовок делится по ` - ` (правило §4), поэтому сессия проекта `app` может поднять окно папки `my - app`, если окна `app` нет. Обратный случай (корень `my - app`) своего окна не найдёт и уйдёт в запасной путь.
- Приложение Desktop (Codex, Claude), главное окно которого скрыто (в трее), не найдено; обход идёт выше по родителям до `explorer.exe`, и если там есть другой процесс с видимым окном (например, терминал, из которого запустили приложение), поднимется его окно, а в журнале будет `Focused`. Вероятность мала, случай «в трее» не измерен; принятое ограничение.
- Предел реального pid: передаётся только pid агента, время создания не сверяется; если pid переиспользован до обработки выхода процесса, обход начнётся не с того процесса. Окно для этого ничтожно.
- `ShowWindow` для свёрнутого окна, поток которого завис, может заблокировать поток переключения (интерфейс не страдает).
- Заголовок окна длиннее 511 символов UTF-16 обрезается; если имя папки оказалось за обрезкой, срабатывает запасной путь.
- Поток переключения не перехватывает паники: профиль `release` собран с `panic = "abort"`, поэтому `catch_unwind` бесполезен. Защита в том, что в коде переключения нет мест паники (срез заголовка защищён `is_char_boundary`, срез буфера — длиной ответа системы).

- Windows может отказать в передаче фокуса: тогда окно только мигает (`Flashed`). Это ожидаемая граница, не ошибка.
- Окно на другом виртуальном рабочем столе: подъём либо переключает стол, либо только мигает, зависит от системы. Особых действий не делаем.
- Заголовок окна редактора, переименованный пользователем или расширением, перестаёт совпадать: срабатывает запасной путь.
- Два окна с одинаковым именем папки: запасной путь с полным корнем.
- Claude Desktop и Codex Desktop: выбор конкретной сессии возможен только при подтверждении замером S3; без него поднимается приложение целиком.
- Обход родителей ограничен `MAX_ANCESTORS` = 8 в `focus/win.rs` (в ретрансляторе подпроекта 1 своя константа `MAX_ANCESTOR_STEPS` = 6); если окно-владелец дальше, срабатывает запасной путь.

## 10. Приёмка

1. Cursor с двумя окнами: клик по сессии одного проекта выводит нужное окно вперёд (в том числе из свёрнутого).
2. VS Code: то же.
3. Claude Desktop: клик выводит окно приложения вперёд.
4. Codex Desktop: окно видно — выводится (проверено); окно в трее — запасной путь открывает Проводник (пока замера протокола нет; не измерено).
5. Два окна редактора с одной папкой: запасной путь, без вывода «наугад».
6. Невозможный подъём: мигает кнопка на панели задач, в журнале `outcome=Flashed`.
7. В журнале нет заголовков окон и путей; `cargo test --workspace` без предупреждений; 0 % CPU при скрытом островке (замер как в подпроекте 1).
