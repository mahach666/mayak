# Mayak: заполненность контекста в строке сессии

Дата: 2026-10-06. Статус: на согласовании. Идея №2 из `docs/superpowers/ideas/2026-10-06-mayak-next-ideas.md`.

## 1. Цель и решения пользователя

В строке каждой сессии острова видно, насколько заполнен её контекст. Так заранее понятно, какой сессии скоро понадобится сжатие или новый тред.

1. **Codex:** процент и тонкая полоска, потому что размер окна Codex пишет сам. **Claude:** только число токенов (`612k`), потому что размера окна в данных Claude нет, а угадывать его по модели мы не будем.
2. **Только заполненность.** Расхода за сессию нет ни в строке, ни в подсказке.
3. **Цвет (только Codex):**
   - серый до 80 %;
   - жёлтый с 80 %;
   - красный с 95 %.

   Без звука, без уведомлений, без влияния на счётчики и тревоги.

**Вне объёма:** расход токенов за сессию, лимиты подписок (идея 1), глобальная статистика (идея 3), хранение на диске.

**Правила проекта сохраняются:**
- Читаются **только числа**. Текст запросов и ответов не читается и не хранится.
- Нет нового опроса и таймеров: числа берутся из уже существующих хвостов файлов (rollout Codex, транскрипт Claude).
- Существующие виды не меняются, кроме новой метки в строке сессии.

## 2. Данные

Замер на файлах пользователя, 2026-10-06, только числовые поля.

### 2.1 Codex (rollout)

Запись `{"type":"event_msg","payload":{"type":"token_count","info":{…}}}`:
- `info.last_token_usage.total_tokens` — **заполненность**: токены последнего запроса, то есть вход с кэшем плюс выход.
- `info.model_context_window` — **размер окна** (например, 258 400).
- `info` может быть `null` (до первого ответа). Такая запись не меняет текущее значение.

В парсере `parse_rollout_line` (`observe/codex.rs`) эта строка сейчас разбирается как `Other`. Она станет `RolloutRecord::Tokens { used: u64, window: Option<u64> }`:
- `used` берётся из `last_token_usage.total_tokens`;
- `window` берётся из `model_context_window`, если это положительное целое.

Если `info` отсутствует или нет `total_tokens`, запись остаётся `Other`.

### 2.2 Claude (транскрипт)

У записи ассистента `message.usage`. **Заполненность** — это сумма `input_tokens + cache_read_input_tokens + cache_creation_input_tokens + output_tokens`. Отсутствующее поле считается за 0. Если нет ни одного из четырёх полей, значения нет.

Окна нет. Его нет ни в транскрипте, ни в `~/.claude/sessions/<pid>.json`.

> Обновлено идеей №4 («Модель и настоящее окно контекста у сессий Claude»): окно берётся из таблицы окон моделей по `message.model` последнего ответа основной цепочки (`observe/claude_transcript.rs`, `WINDOWS`). Модель не из таблицы — окна нет, как раньше. Модель показывается в подсказке метки.

Разбор встраивается в существующий разбор транскрипта (`observe/claude_transcript.rs`). Он берёт **последнюю** запись ассистента с `usage` из прочитанного куска.

### 2.3 Поведение

- Значение — последнее прочитанное. Оно заменяет предыдущее, даже если новое меньше: после сжатия контекста число падает.
- Оно живёт в памяти, пока жива сессия. На диск не сохраняется.
- Когда сессия только что открыта и транскрипт или rollout читается с конца (как сейчас), значение появится с первым новым ответом.

## 3. Модель и снимок

- У `Session` (`observe/model.rs`) появляется поле `context: Option<ContextFill>`, где `ContextFill { used: u64, window: Option<u64> }`. Его обновляют записи §2. Больше оно ни на что не влияет: фазы, счётчики, hold, aggregate, тревоги и звуки прежние.
- `SessionView` получает поле `context: Option<ContextFill>` с `#[serde(skip_serializing_if = "Option::is_none")]`. JSON: `{"used": 612000, "window": 1000000}`, а при отсутствии окна поле `window` опускается.
- У «немых» строк (`silent:<id>`) поля нет.

## 4. Остров

В строке сессии (`views/sessions.ts`) появляется метка **перед временем**. Если `context` нет, метки нет.

| Агент | Вид | Цвет |
|---|---|---|
| Codex (`window` есть) | круг 12 px, заполненный по часовой стрелке от верха на процент, + `62%` (вместо полоски 24×3 px — по замечанию пользователя при приёмке) | серый < 80 %, жёлтый 80–94 %, красный ≥ 95 %; цвета из существующей палитры острова (как у тонов `waiting`/`error`) |
| Claude или любое `window = None` | `612k`, `1.2M`, `950` | серый, без полоски |

- **Формат числа:**
  - меньше 1000 — как есть;
  - меньше миллиона — `Nk` (округление вниз до целого);
  - миллион и больше — `N.NM` (одна цифра после точки, округление вниз).
- **Процент** — `floor(used / window × 100)`, не больше 100.
- Метка не меняет клик по строке: своего обработчика у неё нет, нажатие уходит строке. С идеи №4 у неё есть подсказка (использовано из окна, процент, модель Claude), поэтому в строке сессии она принимает наведение (`.sess-row .sess-ctx`). Claude с известным окном получает круг, процент и цвета Codex.
- Новые стили только добавляются (`.sess-ctx`), существующие не меняются.

## 5. Тесты и приёмка

**Тесты (Rust):**
- Codex `parse_rollout_line`:
  - `token_count` с `info` даёт `Tokens { used, window }`;
  - `info: null` даёт `Other`;
  - без `model_context_window` получается `window: None`;
  - нулевое или отрицательное окно даёт `None`.
- Claude: сумма четырёх полей; отсутствующие поля считаются как 0; запись без `usage` ничего не меняет; из куска берётся последняя запись с `usage`.
- Модель:
  - запись обновляет `context` сессии;
  - меньшее значение заменяет большее;
  - `SessionView` сериализует `context` только при наличии;
  - счётчики и тревоги не меняются.

**TS:** `tsc` и сборка (тестового фреймворка нет). Форматирование чисел и процентов вынести в чистую функцию рядом с `silentText`.

**Приёмка вживую:**
1. У активной сессии Claude в строке видно число токенов, после ответа оно растёт.
2. У сессии Codex видны процент и полоска.
3. Цвета на высоком заполнении: если реальной сессии с 80 %+ нет, это допустимо проверить подстановкой значения через отладочный порт.
4. CPU в покое не меняется.
