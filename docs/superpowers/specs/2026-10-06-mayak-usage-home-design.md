# Mayak: лимиты подписок на домашней странице острова

Дата: 2026-10-06. Статус: на согласовании. Идея №1 из `docs/superpowers/ideas/2026-10-06-mayak-next-ideas.md`.

## 1. Цель и решения пользователя

Домашняя страница острова (вид `overview`) показывает, сколько израсходовано лимитов подписок Claude и Codex и когда они сбросятся.

1. **Домашняя страница отдаётся целиком под использование.** Интеграции (карточка слева и пилюли справа, наследство Coucou) с неё убираются. Их код и настройки не удаляются, только перестают показываться на домашней странице.
2. **Цвет как у метки контекста:** серый до 80 %, жёлтый с 80 %, красный с 95 %. Только на домашней странице, без звука и без выдвигания острова.

**Вне объёма:**
- глобальная статистика токенов (идея 3); позже она займёт место на этой же странице;
- запросы в сеть: Mayak не обращается к API Anthropic или OpenAI, только читает то, что агенты уже записали на диск;
- изменение интеграций и их опроса.

**Правила проекта сохраняются:**
- читаются только нужные числа и даты;
- нет опроса в спрятанном состоянии;
- существующие виды, кроме домашней страницы, не меняются;
- новая страница в стиле приложения.

## 2. Источники (замер 2026-10-06, только структура)

### 2.1 Claude: `~/.claude.json`, ключ `cachedUsageUtilization`

Claude Code кэширует ответ о лимитах:
- `fetchedAtMs` — когда Claude Code получил эти данные (мс эпохи);
- `utilization.five_hour` — окно 5 часов: `utilization` (проценты, число) и `resets_at` (ISO 8601);
- `utilization.seven_day` — неделя, те же поля.

Остальные ключи `utilization.*` и весь остальной файл **не читаются**. В нём есть данные аккаунта, поэтому разбор берёт только этот объект и сразу отбрасывает остальное. Ничего из файла не логируется.

- Файл лежит в профиле пользователя: `%USERPROFILE%\.claude.json`. Если задан `CLAUDE_CONFIG_DIR`, берётся `<CLAUDE_CONFIG_DIR>\.claude.json`, по тем же правилам, что каталог Claude в наблюдателе.
- Окно, у которого `utilization` не число, пропускается. Неразбираемая дата сброса даёт окно без времени сброса.
- **Когда читается** (без опроса и наблюдателя файла): при запуске, при каждом показе острова (`Visible(true)`, тот же сигнал, что перезапускает наблюдатели) и при открытии домашней страницы. Чтение маленькое и идёт в отдельном потоке или на потоке наблюдателя, главный поток не блокируется.

### 2.2 Codex: rollout, запись `event_msg/token_count`

Codex пишет лимиты в `payload.rate_limits` в каждом `token_count`:
- `primary` и `secondary`, каждый либо `null`, либо `{ used_percent: number, window_minutes: number, resets_at: секунды эпохи }`;
- `rate_limit_reached_type` и другие поля не нужны.

- Лимиты общие для аккаунта, поэтому хранится **последнее** прочитанное значение по всем сессиям Codex. Свежесть — время, когда Mayak прочитал запись.
- Разбор встраивается в существующий разбор `token_count` из задачи «контекст»: `RolloutRecord::Tokens` получает поле `limits: Option<CodexLimits>` или становится отдельной записью. Новых чтений файлов нет.

## 3. Модель и снимок

В снимок `SessionsSnapshot` добавляется поле `usage`:

```
usage: {
  claude: { fetchedAtMs, windows: [{ id: "5h"|"7d", percent, resetsAtMs? }] } | null,
  codex:  { seenAtMs,    windows: [{ minutes, percent, resetsAtMs? }] } | null
}
```

- Изменение `usage` меняет `rev`, так же как контекст. На счётчики, тревоги и hold оно не влияет.
- Если источник отсутствует или пуст, поле — `null`.

## 4. Домашняя страница

Вид `overview` отрисовывается заново: два блока, **Claude** и **Codex**.
- **Строка окна:**
  - слева кольцо 12 px и процент — тот же кольцевой индикатор, что у метки контекста, с теми же порогами цвета;
  - название окна: `5h`, `7d`; у Codex оно берётся из `window_minutes`: 300 даёт `5h`, 10080 — `7d`; иначе меньше 1440 минут даёт `Nh`, а от 1440 — `Nd`;
  - справа «resets in 2h 14m» (`in 3d 4h`, `in 12m`, `soon` если меньше минуты); если время сброса уже прошло, показывается `reset`.
- **Свежесть:** если данным больше 10 минут, под блоком мелким текстом «as of 7h ago». У Claude это время его кэша, у Codex — время последнего ответа.
- **Нет данных:** «No data yet». Для Claude подсказка «Claude Code updates it while it runs», для Codex — «Codex reports it with each answer».
- **Обновление текста** («resets in…», «as of…»): при каждой отрисовке и раз в минуту, **только пока домашняя страница на экране**. Пока остров свёрнут или спрятан, таймера нет.
- Кнопки и прочие элементы прежней домашней страницы (интеграции, кнопка «Open» интеграции) с неё убираются. Код `renderIntegrationCard` и пилюль остаётся в репозитории.

## 5. Тесты и приёмка

**Тесты (Rust):**
- Claude-разбор:
  - полный объект;
  - нет `cachedUsageUtilization`;
  - `utilization` не число;
  - неразбираемая дата;
  - лишние ключи игнорируются;
  - отсутствие файла даёт `null`.
- Codex-разбор `rate_limits`:
  - `primary` и `secondary`;
  - `null` у одного из них;
  - отсутствие `rate_limits`.
- Модель:
  - последнее значение побеждает;
  - изменение `usage` меняет `rev`;
  - счётчики и тревоги не меняются.

**TS:** форматирование («5h», «7d», «in 2h 14m», «as of 7h ago», пороги цвета) — чистые функции; `tsc` и сборка.

**Приёмка вживую:**
1. Домашняя страница показывает лимиты Claude: проценты как в `/usage` Claude Code и время сброса.
2. Лимиты Codex появляются после ответа Codex.
3. Пометка свежести у старого кэша.
4. Интеграций на домашней странице нет.
5. CPU в покое не меняется.
