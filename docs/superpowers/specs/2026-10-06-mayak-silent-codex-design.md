# Mayak: «немой» Codex (сессия без хуков), Windows

Дата: 2026-10-06. Статус: реализовано (ветка `feature/silent-codex`), приёмка вживую — §6. Дополняет подпроект 1 (`2026-10-01-mayak-multi-session-core-design.md`, §5.6 «Поток `codex-io`», §7, §15). Основан на ветке подпроекта 2 (переключение окон); с ним не пересекается.

## 1. Проблема и цель

**Наблюдение (2026-10-06).** Тред Codex Desktop в папке, которой больше нет, не может запустить хуки: в «Статистике хуков» Codex каждая запись падает с `Неверно задано имя папки (os error 267)`. Ошибка случается внутри Codex до нашего ретранслятора, поэтому до Mayak не доходит ни одно событие. Сегодня Mayak о такой сессии **ничего не знает** и ничего не говорит: rollout читается только у сессий, о которых сказал хук (подпроект 1, §5.6).

Те же симптомы дают хуки, которые не установлены или не подтверждены (Trust) в Codex.

**Цель.** Если Codex работает, а хуки не доходят, Mayak это замечает и **говорит**: строка в списке сессий острова с причиной и объяснение в Settings → Codex. Без карточки и без звука.

**Принятые решения (пользователь, 2026-10-06).**
1. Вариант «детект «немого» Codex по файлам rollout + предупреждение» (а не полное отслеживание фаз без хуков).
2. Показ: строка в острове + объяснение в Settings → Codex.
3. Правило: сессия «немая», если в её rollout писали за последние **2 минуты** и хука от неё нет.

**Вне объёма.** Фазы работы («работает», «ждёт», «готово») для немой сессии; карточки и звуки для неё; починка причины (папку или Trust пользователь исправляет сам); Claude Code (его файлы сессий читаются без хуков, подпроект 1 §5.5).

**Правила проекта сохраняются.** Только Windows; ничего не пишем в настройки других программ; текст запросов и ответов не читаем и не храним; 0 % CPU при скрытом островке (§4).

## 2. Обнаружение

Новый наблюдатель в потоке `codex-io` (или рядом, тем же способом, что наблюдатель файлов Claude: `ReadDirectoryChangesW` из `observe/win.rs`) следит **рекурсивно** за `<codex_home>/sessions` (по умолчанию `~/.codex/sessions`).

При уведомлении о записи в файл `rollout-*.jsonl`:
1. Файлы `.zst` и другие расширения пропускаются (как `is_readable_rollout`).
2. Если путь уже известен модели как главный rollout сессии с хуками (`transcript_path` из событий хука) — пропускается.
3. Если путь уже разобран наблюдателем раньше — берётся запомненный результат (одна запись на файл в памяти: `id`, `cwd`, `originator`, `parent_thread_id?`, время последней записи).
4. Иначе читается **только первая строка** файла (не больше 256 КиБ): `session_meta`. Берутся `payload.id`, `payload.cwd`, `payload.originator`, `payload.parent_thread_id` (и `source.subagent.thread_spawn.parent_thread_id`, по тем же путям, что в `parse_rollout_line`). Остальное содержимое не читается. Разбор отдельной функцией `silent::parse_session_meta`: `RolloutRecord::Meta` не содержит `originator`.
5. Файл с `parent_thread_id` (подагент) пропускается. Файл без `payload.id` или с первой строкой длиннее 256 КиБ пропускается и считается нечитаемым (здоровье источника, как в §5.6). Пустая или недописанная первая строка (нет перевода строки) и ошибка чтения не запоминаются: файл перечитывается при следующей записи.
6. Результат уходит в модель сигналом `Signal::CodexSilent { id, project, host, folder_exists, written_ms }` (проект, хост и наличие папки вычисляются в потоке `codex-io`).
7. Rollout сессии, которая была с хуками и удалена из модели (`SessionEnd`, снятие, выход процесса), запоминается как пропущенный: немой строкой он больше не станет.

Опроса нет: наблюдатель просыпается только от записи в rollout. Первая строка каждого файла читается один раз, дальше достаточно времени записи из уведомления.

## 3. Модель

`Store` хранит `silent: Map<id, Silent { cwd, host, project, last_write_ms, cause }>`, отдельно от `sessions`.

- `Signal::CodexSilent` создаёт или обновляет запись `last_write_ms = written_ms`, если сессии `id` ещё нет среди обычных сессий Codex (`codex:<id>`).
- Появление **настоящей** сессии с тем же `id` (первый хук) удаляет немую запись: в списке остаётся обычная строка.
- Запись **жива**, пока `now − last_write_ms ≤ 120 с` (2 минуты). Срок проверяется при сборке снимка (при каждом сигнале и при показе островка), **таймеров нет**; просроченные записи в снимок не попадают и удаляются.
- В карте не больше 64 записей; при переполнении удаляется запись с самой старой записью в rollout.
- **Хост** по `originator`: `Codex Desktop` → `CodexDesktop`; всё остальное, включая `codex_vscode`, → `Unknown` (его пишут и VS Code, и Cursor, а пути расширения в rollout нет).
- **Проект** по `cwd` функцией `paths::project_of` (корень git); если папки нет, имя берётся из последнего компонента `cwd`.

### 3.1 Причина (детерминированно)

| Условие (проверяется сверху вниз) | Причина |
|---|---|
| `codexHooks` = `not_installed` | `hooksNotInstalled` — «хуки Mayak не установлены» |
| папки `cwd` не существует | `folderMissing` — «папки треда нет, Codex не может запустить хуки» |
| иначе | `hooksNotReaching` — «хуки установлены, но до Mayak не доходят: проверьте «Статистику хуков» в Codex и подтверждение (Trust)» |

Существование папки проверяется при обнаружении (`Path::is_dir`, один вызов на файл), результат запоминается.

## 4. Снимок и интерфейс

В `SessionView` добавляется необязательное поле `silent: Option<SilentReason>` (`#[serde(skip_serializing_if = "Option::is_none")]`, значения `"hooksNotInstalled" | "folderMissing" | "hooksNotReaching"`). Обычные сессии его не имеют, существующие типы TypeScript остаются совместимыми (поле необязательное).

- Немая сессия попадает в `ProjectView.sessions` своего проекта как `SessionView { agent: Codex, host, phase: Idle, outcome: None, attention: None, acked: true, silent: Some(..) }`: ни на счётчики, ни на `hold`, ни на `aggregate`, ни на звук она не влияет (это строка-предупреждение).
- **Остров:** строка `проект · Codex · без хуков: <причина>` вместо времени и фазы; в стиле существующих строк, приглушённая, без цвета тревоги.
- **Settings → Codex:** пока в снимке есть хотя бы одна немая сессия, в блоке статуса показывается её причина и подсказка из таблицы §3.1 (текст на английском, как остальной интерфейс окна).
- Клик по немой строке ничего не делает: её ключ `silent:<id>` не сессия, окна агента для неё не известно.
- Немая строка не участвует в состоянии островка: проект только с немыми строками не считается «есть сессии» (Mochi и компактный вид как без сессий), строка не прячется в «+N idle». Settings → Codex не показывает причину, если запись уже просрочена.

## 5. Здоровье источника и границы

- Файл `rollout` без `payload.id` в первой строке увеличивает счётчик нечитаемых (`Health::Degraded`), как в §5.6.
- Видна только **живая** (≤ 2 мин) немая сессия; фазы и «ждёт разрешения» для неё не показываются.
- Если Mayak перезапущен посреди работы немого треда, он заметится при следующей записи в его rollout.
- Предупреждение появляется до 2 минут простоя после последней записи; быстро «закрытый» немой тред исчезнет сам.
- Тред, в котором хуки сработали хотя бы один раз, немым не считается (появилась обычная сессия).
- Подагенты не показываются (их `parent_thread_id` задан); у родителя они не учитываются.
- Каталог `sessions` отсутствует или наблюдатель упал с ошибкой: ничего не показывается, наблюдатель запускается снова при следующем показе островка (`Visible(true)` → `CodexInput::Retry`, как у наблюдателя Claude), без опроса.
- Запомненных разобранных файлов не больше 256 (самый старый вытесняется и при следующей записи читается заново).
- Rollout, который уже существовал при запуске Mayak, замечается при следующей записи в него; при переполнении буфера уведомлений пропущенные записи тоже замечаются только при следующей.
- Ложное предупреждение возможно, если хук от сессии придёт позже первой записи rollout: запись исчезнет при первом хуке (§3).

## 6. Тесты и приёмка

- Таблицы тестов (без Win32): разбор `session_meta` (обычный, подагент, без `id`, не JSON), правило 2 минут (граница 120 с), замена немой записи хуком, причина по трём условиям, хост по `originator`, сборка `SessionView` (нет влияния на счётчики, `hold`, звук).
- Тест наблюдателя на временной папке: запись нового `rollout-*.jsonl` даёт один `CodexSilent`; повторные записи не перечитывают файл; `.zst` пропускается.
- Приёмка вживую: (1) тред Codex в несуществующей папке → строка `folderMissing`, исчезает через 2 минуты тишины; (2) без установленных хуков → `hooksNotInstalled`; (3) тред с работающими хуками → немых строк нет; (4) CPU при скрытом островке без Codex-активности остаётся ниже 0,100 % (замер как в подпроекте 1).
