# Mayak: ответы из острова — разрешения Claude и Codex, вопросы Claude

Дата: 2026-10-08. Статус: согласовано с пользователем в диалоге 2026-10-08. Ветка `feature/island-answers` от `main`.

Разведка с источниками лежит рядом: `2026-10-08-mayak-island-answers-research.md`. Ниже ссылки вида «разведка A.1».

Заменяет §G спецификации ночных функций (`2026-10-07-mayak-night-features-design.md`). Ответы пользователя на вопросы §G.3:
1. разрешения Claude — да;
2. вопросы Claude — попробовать;
3. ограниченное ожидание для Codex — попробовать.

## 1. Решения пользователя

1. **Ответы из острова для трёх видов запросов:**
   - разрешение Claude Code (`PermissionRequest`);
   - вопрос Claude Code (`AskUserQuestion`);
   - разрешение Codex (`PermissionRequest`).
2. **Пока карточка открыта, агент ждёт Mayak.**
   - Клик в острове уходит агенту сразу.
   - Когда остров свернулся (сам по автозакрытию или руками), агент сразу отпускается, и вопрос появляется в его окне. Ничего не отклоняется.
   - После этого вопрос остаётся в острове строкой «ждёт тебя» с кнопкой «Открыть» — это уже существующий наблюдатель. Пропадает, когда пользователь ответил в окне агента.
3. **Карточка закрывается как обычное уведомление:** через `autoCloseInterval` (по умолчанию 15 с), курсор над островом держит её открытой.
4. **Верхний предел ожидания — 10 минут**, потом агент отпускается в любом случае.
5. **В разрешении Claude есть кнопка «Всегда»:** Claude Code получает обратно правило, которое сам прислал (`permission_suggestions`), и сам его сохраняет. Mayak в файлы правил ничего не пишет.
6. **У Codex только «Разрешить» и «Запретить»:** его хук не принимает «Всегда» (разведка C.1).
7. **Ничего не включается само.** Хуки пишутся только по клику пользователя, с бэкапом, диффом и подтверждением (существующий поток `hookfile.rs`).

## 2. Поведение

### 2.1 Общее для всех карточек

- **Кнопки:**
  - разрешение Claude: «Разрешить», «Всегда», «Запретить», «В терминале»;
  - разрешение Codex: «Разрешить», «Запретить», «В терминале»;
  - вопрос Claude: варианты и «В терминале».
- **«В терминале», сворачивание острова, автозакрытие** — отпустить агента без решения: ретранслятор выходит с пустым выводом, агент показывает свой обычный запрос.
- **Тихий режим (пауза)** — отпустить сразу, остров не открывается (как сейчас, `approvalDecline`).
- **Глушение в рабочем интервале помодоро:**
  - «пропускать ждущих агентов» включено — карточка показывается;
  - выключено — отпустить сразу.
- **Одна карточка за раз.** Второй запрос, пока открыта первая карточка, отпускается сразу (как сейчас).
- **Смена языка** отпускает открытую карточку перед перезагрузкой (как сейчас).
- **Отказ.** Текст отказа видит модель: `"Denied from Mayak"`, как сейчас.

### 2.2 Разрешение Claude

Вход и ответ — разведка B.1.
- «Разрешить» → `{"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{"behavior":"allow"}}}`.
- «Всегда» → то же с `"updatedPermissions": <permission_suggestions из входа, без изменений>`. Если `permission_suggestions` во входе нет или он пуст, кнопки «Всегда» нет.
- «Запретить» → `"behavior":"deny","message":"Denied from Mayak"`.

### 2.3 Вопрос Claude

Разведка B.2: хук `PreToolUse` с `matcher: "AskUserQuestion"`, Claude Code 2.1.85 и новее.
- **Карточка:**
  - каждый вопрос (1–4) с заголовком и вариантами (2–4) с описаниями;
  - одиночный выбор — клик по варианту, если вопрос один; если вопросов несколько, по одному выбору в каждом;
  - мультивыбор — отметки и кнопка «Ответить».
- **Свой ответ текстом в острове не вводится:** для этого «В терминале».
- **Ответ** → `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"allow","updatedInput":{"questions":<исходный массив без изменений>,"answers":{"<текст вопроса>":"<метка>" | ["<метка>", …]}}}}`.
  - Мультивыбор — массив меток (Claude Code 2.1.136+).
  - `questions` — необрезанная копия из stdin ретранслятора, никогда не та, что прошла через обрезку `MAX_FIELD_LEN`.
- **Payload, который не удаётся разобрать** (не 1–4 вопроса, не 2–4 варианта, нет текста), — отпустить сразу.

### 2.4 Разрешение Codex

Разведка C.1–C.2.
- «Разрешить» / «Запретить» — тот же JSON, что у Claude, без `updatedPermissions`.
- Пока хук ждёт, Codex свой запрос не показывает. После отпускания показывает.
- Диалог Codex «Permissions» (`request_permissions`) хуки не вызывает, поэтому остров на него не отвечает. Наблюдатель по-прежнему показывает такую сессию как ждущую.

### 2.6 Ответил в окне агента — карточка уходит (просьба пользователя, 2026-10-08)

- Касается любой карточки сессии в острове: «Ход завершён», «Ошибка», «Ждёт тебя», а также карточек ответа из §2.2–2.4, если агента уже отпустили.
- Как только наблюдатель видит, что эта сессия пошла дальше (новый ход после пользовательского сообщения, ответ на ожидание, сессия снова работает), карточка устаревает. Тогда:
  - если есть другие неотвеченные уведомления (ожидающие сессии, непросмотренные «готово» или «ошибка»), остров переключается на самое важное из них — с тем же рангом, что у тревог (§10 мультисессионной спецификации);
  - иначе остров сворачивается.
- Решение принимается по снимку наблюдателя, без опроса: никаких новых таймеров.
- Если пользователь сам открыл другой вид (не карточку), остров не трогается.

### 2.5 Тайм-ауты

| Где | Значение | Зачем |
|---|---|---|
| `timeout` хука в `settings.json` / `hooks.json` | 600 с | верхний предел 10 мин (Claude и Codex по умолчанию тоже 600, разведка B.1, C.2) |
| бюджет ретранслятора | 595 с | заканчивает раньше, чем агент убьёт хук |
| ожидание решения в `pipe.rs` | 590 с | заканчивает раньше ретранслятора |
| подтверждение показа карточки (`ACK_TIMEOUT`) | 0,8 с, как сейчас | остров не показал карточку → отпустить |
| карточка в острове | `autoCloseInterval` с курсором вне острова, иначе до решения, не дольше 590 с | |

## 3. Установка и настройки

- **В Settings раздел «Ответы из острова»** вместо блока «Advanced — … (legacy)».
- **Claude:**
  - кнопка «Включить» ставит в `~/.claude/settings.json` две записи:
    - `PermissionRequest`, `timeout: 600`;
    - `PreToolUse` с `"matcher": "AskUserQuestion"`, `timeout: 600`;
  - команда — та же форма, что сейчас (путь в кавычках, прямые слэши, имя события в аргументе);
  - старая запись Mayak (`timeout: 120`, без `PreToolUse`) считается устаревшей: «Обновить»;
  - «Выключить» убирает обе записи;
  - подпись: «Вопросы — Claude Code 2.1.85 и новее».
- **Codex:**
  - кнопка «Включить» меняет у уже установленной группы Mayak запись `PermissionRequest`: `timeout: 600` и `statusMessage: "Waiting for your answer in Mayak"`;
  - остальные события без изменений;
  - после записи показывается подсказка: Codex попросит снова доверить хуки в `/hooks` (разведка C.2, документировано);
  - «Выключить» возвращает `timeout: 10` без `statusMessage`.
  - Если хуки Codex не установлены, сначала обычная установка интеграции Codex.
- **Состояние «включено» читается из файлов агентов** (наши записи с `timeout: 600`), а не из настроек Mayak. Сервер решает, ждать ли ответа Codex, по этому же признаку:
  - запись прочитана при запуске и после каждой установки или снятия;
  - иначе Codex `PermissionRequest` — `Observe`, как сейчас.
- **Безопасность:**
  - всё через существующий поток бэкап → дифф → подтверждение → запись;
  - проверка формы `"hooks"` (Claude) и `check_shape` (Codex);
  - никогда не писать `[hooks.state]` или `trusted_hash` в конфиг Codex;
  - pipe по-прежнему только для SID текущего пользователя;
  - ответ из острова — только явный клик.

## 4. Код

- **Ретранслятор** `windows/hook`:
  - ждёт ответа для Claude `PermissionRequest`, Claude `PreToolUse` (`tool_name == "AskUserQuestion"`) и Codex `PermissionRequest`;
  - бюджет 595 с;
  - хранит необрезанные `tool_input.questions` и `permission_suggestions`;
  - печатает JSON из §2;
  - на «release» или без ответа печатает пустой вывод.
  - **Протокол pipe:** строка ответа — одно из `allow`, `always`, `deny`, `release` или `answer <json answers>`.
  - Фильтр D87 для `AskUserQuestion` в `PermissionRequest` остаётся: там пустой вывод, вопрос задаётся через `PreToolUse`.
- **Сервер:**
  - `pipe.rs`: маршрут `Question` для Claude `PreToolUse`/AskUserQuestion; `Approval` для Codex `PermissionRequest`, когда для Codex включено (иначе `Observe`). Codex-запрос в любом случае уходит наблюдателю;
  - `DECISION_TIMEOUT` 590 с;
  - команды `approval_decision(id, decision)` с `always`, `question_answer(id, answers)`, `approval_decline(id)`.
- **Остров:**
  - карточки разрешения (Claude/Codex) и вопроса;
  - автозакрытие вместо закрепления: свернулся — `approval_decline`;
  - тексты на 7 языках.
- **Settings:** раздел «Ответы из острова», тексты на 7 языках.
- **Документы:** `windows/README.md` (как включить, что Codex попросит доверие), комментарии со словом «legacy» в `hooks.rs`, `pipe.rs`, `island/hooks.ts` обновить.

## 5. Тесты и проверка

- **Ретранслятор (Rust):**
  - JSON каждого ответа (allow, always с suggestions, deny, answer single, answer multi с массивом, answer нескольких вопросов);
  - `questions` эхом без обрезки при длинном тексте;
  - пустой вывод на release и на тайм-аут;
  - Codex `PermissionRequest` ждёт и печатает allow/deny;
  - D87 для AskUserQuestion в `PermissionRequest` по-прежнему пуст.
- **Сервер:**
  - маршруты при включённом и выключенном Codex;
  - разбор строки `answer` от острова;
  - отклонение неверного payload вопроса.
- **Установщики:**
  - Claude: две записи, обновление старой, снятие, отказ при плохой форме;
  - Codex: смена `timeout` и `statusMessage` только у `PermissionRequest`, обратная смена;
  - тесты только на временных файлах.
- **Остров (TS, Node-проверки чистых функций):**
  - разбор вопросов;
  - сборка `answers` (одиночный, мульти, несколько вопросов);
  - видимость «Всегда».
- **Вживую:**
  - **Claude:** разрешение «Разрешить», «Всегда», «Запретить», «В терминале», автозакрытие → вопрос в терминале;
  - **Claude:** `AskUserQuestion` с одиночным и мультивыбором;
  - **Codex:** разрешение после повторного доверия в `/hooks`;
  - нажатие в окне агента после отпускания убирает строку «ждёт тебя».
  - Установка хуков на настоящих файлах — только по подтверждению пользователя в его сессии: агент сам в `~/.claude/settings.json` и `~/.codex` не пишет.
